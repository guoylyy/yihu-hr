# 人事考勤（以虎 One 应用）

插在 [以虎 One](../yihu-one) 上的代码应用：把**钉钉、飞书、企业微信**三家的打卡结果汇到一处，加上**请假审批**和**年假余额**。人以平台为准，登录走平台统一认证，AI 助手经 MCP 能查考勤、请假、审批。

以后的人事功能（排班、加班、调休登记、入转调离……）都在这个应用里长，应用代码 `hr` 定了不再改。

## 功能

| 谁 | 能做什么 |
| --- | --- |
| 员工 | 看自己每天的打卡（三家合在一起）、迟到早退缺卡；请假（可请半天）、撤销；看年假 / 调休余额和流水 |
| 部门负责人 | 审批下属请假；看本部门及下级部门某天的出勤、月度报表 |
| 人事 | 看全公司；补录打卡；发年假（按法定工龄自动折算）、调整余额、年末结转；节假日 / 调休；假期类型；同步状态；规则设置 |
| AI 助手 | 「我这个月迟到几次」「我还有几天年假」「帮我请明天下午的假」「今天谁没打卡」「有什么等我批的」 |
| 老板简报 | 实现了平台的三个标准工具，出勤和待审批会出现在每日经营简报、管理层首页上 |

谁是人事：平台管理员自动是；其他人由人事在「设置 → 人事成员」里加。谁是负责人：平台部门的负责人（统一登录带来的 `leaderOf`，本人打开过一次应用后生效）。其他人只能看自己。

## 怎么接三家的打卡

打卡数据**只读**，每 30 分钟（可调）把最近 3 天的结果重拉一遍（补卡、改结果会改动前几天），按「来源 + 记录 id」去重。人对人用平台用户主数据里的 `dingUserId` / `feishuOpenId` / `wecomUserId`，所以**先在平台「管理 → 登录方式」配好对应的登录方式并同步通讯录**。

凭证是密钥，管理员写进服务器上的 `apps/hr/.env`（不进代码库），只配要用的那家：

| 来源 | 变量 | 开放平台上要做的 |
| --- | --- | --- |
| 钉钉 | `DINGTALK_APP_KEY` `DINGTALK_APP_SECRET` | 企业内部应用（建议就用平台登录那个），开通考勤「打卡结果」读权限 |
| 飞书 | `FEISHU_APP_ID` `FEISHU_APP_SECRET` | **必须和平台登录用同一个应用**（open_id 才对得上）；开通 `attendance:task:readonly`（导出打卡数据）和 `contact:user.employee_id:readonly`（获取用户 user ID）。拿不到 user ID 权限时，按平台上的工号对 |
| 企业微信 | `WECOM_CORP_ID` `WECOM_CHECKIN_SECRET` | 「应用管理 → 打卡」系统应用的 Secret（不是平台登录用的自建应用），并把 API 可见范围设为全员 |

改完 `.env` 在控制台重启应用。之后在「设置 → 打卡同步」能看到每家配没配、最近的同步结果、**对不上身份的人**（这些人要先在平台上绑定账号），也可以手动同步、补拉历史（一次最多 62 天）。

接口限制已按各家处理：钉钉一次 50 人 7 天、飞书一次 50 人、企业微信一次 100 人 30 天。

### 考勤状态怎么算

一个人一天 = 三家打卡结果 + 这里批的假 + 工作日历：

- 请满一天假 → 请假（打卡系统不知道这边批的假，报的缺卡 / 旷工不算）；请半天假 → 时间类异常不算，地点异常照算
- 人事补录的打卡覆盖同一天同一类（上班 / 下班）的同步结果
- 工作日没有任何记录 → 「无记录」（没排班或没同步到），不当旷工
- 迟到、早退、缺卡、旷工以打卡系统的判定为准（班次、弹性规则都在各家后台里配），这里不重算

## 请假与年假

- 天数 = 区间里的工作日（扣周末、节假日，算调休上班日），按半天计；不能和自己已有的请假重叠
- 审批人：人事给这个人指定的 → 主部门往上找最近的负责人 → 都没有就由人事审批。提交、审批结果经平台的钉钉 / 飞书 / 企业微信通知
- 年假、调休扣余额：提交时看「可用 = 余额 − 待审批占用」，批准时扣、撤销时退。余额只有流水（发放 / 结转 / 调整 / 扣减 / 退回 / 清零），不改不删，随时能对账
- **年假发放**按《职工带薪年休假条例》：累计工龄满 1 年 5 天、满 10 年 10 天、满 20 年 15 天；新入职、年中跨档位的按当年剩余日历天数逐日折算，不足 1 天不给（可在设置里改成精确到半天）。需要人事填每人的「入职日期」「参加工作日期」（假期余额页可批量导入）。重复点「发放」只补差额，改了日期再点一次就重新核算
- 年末结转：把当年剩余年假清零，最多 N 天（设置里配，默认 0）转入下一年
- 每年国务院公布放假安排后，在「设置 → 节假日」录一次（`2026-10-01 休 国庆节`、`2026-10-10 班 国庆调休`）

## 目录

```
yh-app.json        应用清单（code: hr，带数据库、MCP）
Dockerfile         一个容器：后端托管前端构建产物，启动时 prisma migrate deploy
release.sh         发布：测试 → main 推到 release（manual 模式，管理员在控制台点发布）
backend/
  prisma/          数据模型和迁移
  src/index.js     入口：/health、/mcp、统一登录、/api、静态文件
  src/lib/         yh-one.mjs（平台 SDK，以平台仓库 console/frontend/public/sdk/ 为准）、日期、年假、考勤状态（纯函数）
  src/providers/   钉钉 / 飞书 / 企业微信适配器：拉打卡结果 → 统一形状
  src/services/    权限（access）、通讯录、同步、考勤、请假、余额、节假日、设置、留痕
  src/mcp.js       AI 工具
  test/            单元测试（不需要数据库）
frontend/          Vue 3 + Element Plus，hash 路由，相对路径（挂在 /apps/hr/ 下）
```

## 本地开发

```bash
# 起一个 MySQL 8，建库 yihu_hr_dev
cd backend && cp .env.example .env && npm i && npx prisma migrate deploy && npm run dev   # :3006
cd frontend && npm i && npm run dev                                                       # :5186，/api 代理到 :3006
cd backend && npm test
```

不配 `YH_CLIENT_ID` 时是本地开发模式：不走统一登录，以 `DEV_USER_ID` 的身份访问（`DEV_ADMIN=1` 当平台管理员，`DEV_LEADER_OF=10,11` 当这些部门的负责人）；员工数据不会从平台同步，自己往 `Employee` 表里放几个人。生产环境（`NODE_ENV=production`）永远不会走这个模式。

## 装到平台上

1. 把仓库推到 Git，`./release.sh` 推出 `release` 分支
2. 管理员在控制台「管理 → 应用 → 从 Git 安装应用」装上（或服务器上 `yh add` + `yh up`）；平台自动建库、登记统一认证、注入 `YH_*` 和 `DATABASE_URL`
3. 管理员在服务器上写 `apps/hr/.env`（上面的打卡凭证），控制台重启应用
4. 打开应用 → 设置：看同步状态、录节假日、加人事成员；假期余额：导入入职 / 参加工作日期，发放年假

上线前按平台的[上线检查清单](../yihu-one/console/docs/devcenter/checklist.md)用员工、负责人、人事三种身份各走一遍。
