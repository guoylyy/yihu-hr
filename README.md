# 人事考勤（以虎 One 应用）

插在 [以虎 One](../yihu-one) 上的代码应用：把**钉钉、飞书、企业微信**三家的打卡结果和审批通过的**请假、出差、外出**汇到一处，做考勤的统计和全景（月历、团队矩阵），加上**年假余额**和人员档案。**请假、审批都在钉钉 / 飞书 / 企业微信里走，本应用只同步、只统计，不审批。** 人以平台为准，登录走平台统一认证，AI 助手经 MCP 能查考勤、请假，能导入员工信息。

以后的人事功能（排班、加班、调休登记、入转调离……）都在这个应用里长，应用代码 `hr` 定了不再改。

## 功能

| 谁 | 能做什么 |
| --- | --- |
| 员工 | **考勤月历**：一格一天，看到状态、上下班时间、请假 / 出差 / 外出、迟到早退缺卡，点一天看每次打卡；下面是原始记录，能导出；「我的假期」看年假 / 调休余额和流水、同步来的请假出差记录；「我的档案」看自己的合同；看负责人记的 1v1 纪要、勾掉自己的待办 |
| 部门负责人 | **团队考勤矩阵**：本部门及下级部门每人一行、每天一格，加上这个月的汇总，能排序、导出月报；点名字看这个人的月历；**人员全景**和下属的**画像**；看下属的合同和人员成本（人事可在设置里关掉）；给下属记 **1v1** |
| 人事 | 看全公司；补录打卡；**智能导入**（花名册、余额表或一段话 → 档案和余额）；发年假（按法定工龄自动折算）、调整余额、年末结转；节假日 / 调休；假期类型；同步状态；规则设置；**档案、合同、人员成本**的录入和管理；给任何人记 1v1 |
| AI 助手 | 「我这个月迟到几次」「我还有几天年假」「我今年请了几天假」「今天谁没打卡」「这个月谁迟到最多」「张三的情况」「最近谁的合同要到期」「帮我记一下和李四的 1v1」「研发部人员成本多少」「把李四的年假余额改成 5 天、入职日期 2021-03-01」 |
| 老板简报 | 实现了平台的三个标准工具：出勤、请假出差、合同到期、1v1 覆盖率、人员成本会出现在每日经营简报、管理层首页上；人事的待决事项里有「快到期的劳动合同续不续签」 |

谁是人事：平台管理员自动是；其他人由人事在「设置 → 人事成员」里加。谁是负责人：平台部门的负责人（统一登录带来的 `leaderOf`，本人打开过一次应用后生效）。其他人只能看自己。

## 怎么接三家的打卡

打卡和请假 / 出差 / 外出都**只读**，每 30 分钟（可调）把最近 3 天的结果重拉一遍（补卡、改结果、撤销请假会改动前几天），请假往后多拉 30 天（提前请的假也看得到），按「来源 + 记录 id」去重。人对人用平台用户主数据里的 `dingUserId` / `feishuOpenId` / `wecomUserId`，所以**先在平台「管理 → 登录方式」配好对应的登录方式并同步通讯录**。

凭证从哪来：

- **钉钉、飞书**：直接用以虎 One「管理 → 登录方式」里配好的那个企业内部应用（平台 0.6.4+ 给可信应用发 access_token，密钥不出平台），不用再配一遍。要在钉钉 / 飞书开发者后台给**那个应用**开通考勤权限：钉钉「考勤打卡结果」读权限和「查询请假状态」接口的权限；飞书 `attendance:task:readonly`（导出打卡数据）、「获取审批通过数据」（user_approvals）接口要的权限，和 `contact:user.employee_id:readonly`（获取用户 user ID，拿不到时按平台上的工号对）
- **企业微信**：打卡要用「应用管理 → 打卡」这个系统应用的 Secret（和平台登录用的自建应用不是一个），管理员写进服务器上的 `apps/hr/.env`：`WECOM_CORP_ID`、`WECOM_CHECKIN_SECRET`，并把打卡的 API 可见范围设为全员
- 要用和平台不同的钉钉 / 飞书应用，也可以在 `apps/hr/.env` 写 `DINGTALK_APP_KEY` `DINGTALK_APP_SECRET` / `FEISHU_APP_ID` `FEISHU_APP_SECRET`，写了就优先用（飞书必须是同一个应用，open_id 才对得上）

改完 `.env` 在控制台重启应用。之后在「设置 → 打卡同步」能看到每家配没配、最近的同步结果、**对不上身份的人**（这些人要先在平台上绑定账号），也可以手动同步、补拉历史（一次最多 62 天）。

接口限制已按各家处理：钉钉打卡一次 50 人 7 天、请假一次 100 人；飞书一次 50 人；企业微信一次 100 人 30 天。

各家能拿到的假勤：

| | 请假 | 出差 | 外出 | 说明 |
| --- | --- | --- | --- | --- |
| 飞书 | ✓ 带类型和时段 | ✓ | ✓ | `user_approvals/query`，只要已通过的 |
| 企业微信 | ✓ 带类型 | ✓ | ✓ | 打卡日报 `getcheckin_daydata` 的假勤统计，按天给时长，没有起止时刻 |
| 钉钉 | ✓ 只有时段和时长，没有类型 | — | — | `getleavestatus`；钉钉的出差 / 外出只有逐人逐天的接口（调用量太大），不同步。没有类型的请假照样算进考勤，只是不扣余额 |

拉打卡成功、拉请假失败（多半是没开权限）时，同步记录照样算成功，「说明」里写请假没同步的原因。

### 考勤状态怎么算

一个人一天 = 三家打卡结果 + 三家同步来的请假 / 出差 / 外出 + 工作日历：

- 请满一天假 → 请假；出差满一天 → 出差（报的缺卡 / 旷工不算）；请假、出差、外出不满一天 → 时间类异常不算，地点异常照算
- 请假落到每天占多少：各家报了时长（天 / 小时）的，按和上下班时段（设置里配，默认 9:00 ~ 18:00）的重叠比例分到工作日；按小时的按「一天几小时」（默认 8）折成天；企业微信按天给，直接用
- 人事补录的打卡覆盖同一天同一类（上班 / 下班）的同步结果
- 工作日没有任何记录 → 「无记录」（没排班或没同步到），不当旷工；还没到的日子不算
- 迟到、早退、缺卡、旷工以打卡系统的判定为准（班次、弹性规则都在各家后台里配），这里不重算

## 请假与年假

- **请假、出差、外出在钉钉 / 飞书 / 企业微信里提交和审批**，本应用不审批、不发通知，只同步已通过的。旧版（0.2.x）在本应用里批过的请假照常算进考勤和余额
- 各家的假期名称按**名称**对上「设置 → 假期类型」（年休假 = 年假、调休假 = 调休）；对上「扣余额」的类型就自动扣余额，各家撤销了（重拉时没有了）就退回。按记录对账：每条记录在流水里的扣减之和 = 它应扣的天数，重复同步、时长改了都只补差额
- 余额只有流水（发放 / 结转 / 调整 / 导入 / 扣减 / 退回 / 清零），不改不删，随时能对账；「导入」是把余额设为某个数（补一条差额）
- **年假发放**按《职工带薪年休假条例》：累计工龄满 1 年 5 天、满 10 年 10 天、满 20 年 15 天；新入职、年中跨档位的按当年剩余日历天数逐日折算，不足 1 天不给（可在设置里改成精确到半天）。需要人事填每人的「入职日期」「参加工作日期」（用智能导入批量导）。重复点「发放」只补差额，改了日期再点一次就重新核算
- 年末结转：把当年剩余年假清零，最多 N 天（设置里配，默认 0）转入下一年
- 每年国务院公布放假安排后，在「设置 → 节假日」录一次（`2026-10-01 休 国庆节`、`2026-10-10 班 国庆调休`）

## 考勤 / 考核豁免

有的人不该算进统计（董事一般不打卡，算进去出勤率、人均成本都会失真）。人事给这些人打上豁免：

| | 考勤统计（团队矩阵、出勤率、今日出勤、考勤异常提醒） | 人员全景的指标（人数、司龄、年龄、1v1 覆盖、风险、按部门、分布） | 人员成本的统计（全景、简报里的总额、人均） |
| --- | --- | --- | --- |
| 免考勤（如高管、长期外派） | 不算 | 照算 | 照算 |
| 免考勤、不参与考核（如董事、监事、外部顾问） | 不算 | 不算（单独计数） | 不算 |

- 在画像「编辑档案」里设（可写原因），或在人员全景里勾选几个人批量设；智能导入的「考勤豁免」列（免考勤 / 董事 / 不参与考核 / 正常）、AI 助手的 `import_employee_data` 也能设
- 被豁免的人照常同步打卡、在名单 / 档案 / 成本表里能看到（带标签）；团队考勤可以勾「显示免考勤的人」看他们（列在最后，不算进合计）
- 不参与考核的人不催 1v1、不提醒状态 / 待办，也不提醒「没有劳动合同 / 保密协议」（董事本来就不一定有）；签了劳动合同快到期的照样提醒
- 规则在 `lib/exemption.js`

## 智能导入

人事在「管理 → 智能导入」把现有的员工资料一次导进来，不用一个个点：

- **上传表格**（Excel / CSV，在浏览器里解析）：表头先按规则对（入职日期 / 入职时间 / 到岗日期 …… 都认），对不上的列把表头和几行样例交给以虎 One 的**大模型**认；值先按规则规范（`2021.3.5`、`2021年3月`、Excel 日期序列号、「全日制本科」、「劳务派遣」、「8 年 3 个月」……），规则解析不了的再交给模型。列对应可以手工改了重新识别
- **说一段话 / 粘贴**：「张三 2021 年 3 月入职，本科；李四年假还剩 5 天」，模型抽成一条条记录；粘贴的是带表头的表格就按表格认（不用模型）
- 能导：入职 / 参加工作 / 转正 / 离职 / 出生日期、性别、学历、院校、专业、职级、用工类型、标签、考勤 / 考核豁免和原因、工龄 / 司龄（推算参加工作 / 入职日期，只在没直接给日期时用）、各类扣余额的假的**余额**（设为这个数）
- 按工号、再按姓名对人（重名要工号）；**先出预览**（谁、哪一项、从什么改成什么、哪些写法看不懂），勾选确认后才写入
- 模型给的值也要再过一遍规则校验，格式不对的不收；没接入平台（本地开发）时只用规则。留痕只记导了几个人几项
- AI 助手（MCP 的 `import_employee_data`）走同样的规则：先预览给用户看，确认后写入

## 人员全景与画像

- **画像**（每个人一页）：档案（部门、职级、用工类型、入职 / 转正 / 离职、司龄、工龄、年龄、学历、院校专业、标签）、合同与协议、人员成本（近 12 个月、今年累计、构成、标准月成本）、考勤异常和假期、1v1 次数和状态走势，以及**要留意的事**：没有有效劳动合同、劳动合同快到期（没续签的）、试用期快结束、没有保密协议、太久没 1v1、最近 1v1 状态偏低、1v1 待办没完成、考勤异常多、竞业限制履行中
- **人员全景**（公司 / 本部门的人员蓝图）：人数、入离职、平均司龄和年龄、有风险的人、合同到期 / 缺失、试用期、1v1 覆盖率、状态偏低、人员成本和人均；按部门汇总；司龄、年龄、学历、用工类型、成本构成的分布；人员名单按标记筛（点指标卡片即筛）
- 档案字段由人事在画像里「编辑档案」；姓名、部门、工号以平台为准，不在这里改

## 合同与协议

- 类型：劳动合同、保密协议、竞业限制协议、知识产权归属协议、培训服务期协议、实习协议、劳务协议、其他。一人可以有多份；**续签 = 新建一份**（从上一份「续签」进去，生效日自动接上一份到期日的次日），旧的保留备查，不再提醒
- 保存时按《劳动合同法》校验：固定期限要写到期日；**试用期上限**（第十九条：不满 3 个月和按任务的不得约定，3 个月 ~ 1 年 1 个月，1 ~ 3 年 2 个月，3 年以上或无固定期限 6 个月）；**竞业限制**期限 1 ~ 24 个月（第二十四条），没约定补偿金会提醒
- 状态：有效、即将到期（到期前 N 天，设置里配，默认 60）、已到期、已解除；竞业限制按档案里的**离职日期**起算：在职时「已签」，离职后「履行中」，期满「已到期」
- 签好的扫描件放以虎 One 的**文件存储**（平台 0.6.0+，管理员在「管理 → 系统设置 → 文件存储」配七牛云）：浏览器直传，下载由应用检查权限后跳 5 分钟有效的地址，不进数据库、不进代码仓库。没配文件存储时合同信息照常录，只是不能传文件
- 谁能看：人事全部；负责人看下属的（「设置 → 规则」里能关）；每个人看自己的。只有人事能改

## 人员成本

- 成本表：每人每月每类一个数（工资、奖金、社保单位部分、公积金单位部分、福利、培训、设备办公、招聘、竞业补偿、经济补偿、其他），金额是**单位承担的成本**，不是到手工资
- **标准月成本**（每人：月应发工资、社保、公积金、福利）+ 「生成某月成本」：按标准补齐这个月在职的人，离职后竞业限制期内的自动加上每月补偿；已经录过的数不动。奖金、培训等一次性的点格子录或批量导入（「工号或姓名, 类别, 金额, 备注」，可从表格粘贴）
- 谁能看：人事全部；负责人看下属的（「设置 → 规则」里能关），看不到自己的；员工看不到。金额不进操作留痕和平台使用数据

## 1v1

- 负责人给下属记（人事给任何人记）：日期、时长、话题、纪要、**状态 1 ~ 5**、待办（本人 / 负责人，带期限）、下次时间、**私人备注**
- 本人能看到标了「本人可见」的纪要和待办（看不到状态和私人备注），能勾掉自己的待办；记录人上面的负责人、人事能看全部；私人备注只有记录人和人事能看
- 「1v1」页左边是我的下属名单，按「多久没谈」排，超过建议间隔（设置里配，默认 30 天）的标出来；AI 助手能记（「帮我记一下和张三的 1v1：……」）

## 本地开发

```bash
# 起一个 MySQL 8，建库 yihu_hr_dev
cd backend && cp .env.example .env && npm i && npx prisma migrate deploy && npm run dev   # :3006
cd frontend && npm i && npm run dev                                                       # :5186，/api 代理到 :3006
cd backend && npm test
```

不配 `YH_CLIENT_ID` 时是本地开发模式：不走统一登录，以 `DEV_USER_ID` 的身份访问（`DEV_ADMIN=1` 当平台管理员，`DEV_LEADER_OF=10,11` 当这些部门的负责人）；员工数据不会从平台同步，自己往 `Employee` 表里放几个人。生产环境（`NODE_ENV=production`）永远不会走这个模式。

## 装到平台上

1. 把仓库推到 Git，`./release.sh` 推出 `release` 分支
2. 管理员在控制台「管理 → 应用 → 从 Git 安装应用」装上（或服务器上 `yh add` + `yh up`）；平台自动建库、登记统一认证、注入 `YH_*` 和 `DATABASE_URL`
3. 管理员在服务器上写 `apps/hr/.env`（上面的打卡凭证），控制台重启应用
4. 打开应用 → 设置：看同步状态、录节假日、加人事成员；假期余额：导入入职 / 参加工作日期，发放年假

上线前按平台的[上线检查清单](../yihu-one/console/docs/devcenter/checklist.md)用员工、负责人、人事三种身份各走一遍。
